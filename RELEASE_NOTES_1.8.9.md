# ИИкона 1.8.9: понятные ошибки запросов в агентской петле

Если модель обращалась к несуществующему полю, MCP-сервер возвращал общее
`Internal error`. Модель не видела, что исправлять. Теперь отказ выполнения
`execute_query` передаётся как результат инструмента с `isError=true`,
кодом причины и кодом обращения. Например: `Поле не найдено "Модели.НетТакогоПоля"`.
Модель может уточнить структуру объекта и исправить запрос в следующем раунде.

## Что изменилось

- Для ошибок выполнения запроса сохраняется краткая техническая причина без
  стека BSL. Полные подробности остаются в журнале регистрации.
- Локальный вызов, удалённая база и агент используют исходный код обращения.
  При передаче отказа новая дублирующая запись ошибки не создаётся.
- Аудит MCP отмечает `isError=true` как неуспешный вызов.
- Синтаксические ошибки протокола, неверные аргументы и ограничения безопасности
  сохраняют прежний порядок обработки. Запросы выполняются с правами пользователя;
  разрешения на изменение данных не добавлены.

Поле виртуальной таблицы зависит от метаданных конфигурации. Сообщение
«Поле не найдено» само по себе не означает, что виртуальные таблицы не поддерживаются.

## Где искать подробности

Ошибка выполнения запроса записывается в стандартный журнал регистрации,
событие `КИИ.СерверMCP.Диспетчер`. Ищите её по коду обращения из ответа.
Для других ошибок агента сохраняется событие `КИИ.АгентАнализа.ОшибкаИнструмента`.

Журнал мониторинга заполняется сборщиком. Наличие события в стандартном журнале
не означает, что сбор уже выполнен. Проверьте настройки, состояние регламентных
заданий, выбранные уровни и период. При первом сборе без сохранённой позиции
берутся последние пять минут; прежняя история автоматически целиком не импортируется.
На серверном стенде реальное событие MCP проверено через штатное чтение,
дедупликацию и запись мониторинга с последующим откатом проверочной транзакции.
Настройки и история конкретной внешней базы этим не подтверждаются.

## Обновление

1. Сделайте резервную копию базы.
2. Замените расширение ИИКона файлом `IIkona-1.8.9.cfe` и выполните штатное
   обновление конфигурации базы. Завершите старые пользовательские сеансы,
   если платформа запросит это при обновлении.
3. Если используется удалённая MCP-база, обновите ИИкону и в ней, и на стороне
   вызывающего клиента: обе стороны участвуют в передаче подробностей отказа.
4. Повторите запрос с заведомо неверным полем, затем правильный запрос.
   В первом ответе должны быть причина и код обращения; второй должен выполниться.
