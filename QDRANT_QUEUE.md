# Очередь Qdrant — версия 1.7.1

Дата: 11.10.2026. Проверено на отдельной серверной базе 1С 8.3.27.1989 и БСП 3.1.11.392, а также при обновлении отдельной копии 1.6.3. Для перехода требуется пересборка коллекций Qdrant.

## Настройки и вызовы

Прежние входы `КИИ_RAGQdrant.ПоставитьВОчередь`, `ПоставитьВОчередьБезопасно`, `ОбработатьОчередь` и `ПересобратьКоллекцию` сохранены. Они используют новый модуль `КИИ_ОчередьQdrant`.

Для управляемого запуска:

```bsl
Настройки = КИИ_ОчередьQdrant.ПараметрыОбработки();
Настройки.РазмерПакета = 32;
Настройки.КоличествоИсполнителей = 4;
Настройки.КодМодели = "";
Итог = КИИ_ОчередьQdrant.Обработать(Настройки);
```

Пакет содержит до 32 операций по умолчанию, допустимый предел — 64. Один проход выбирает до 256 заданий. Число исполнителей — от 1 до 4 на проход; в файловой базе используется синхронный обработчик. Пустой код модели обрабатывает все модели, заполненный ограничивает выборку. Дополнительно пакет ограничен 131 072 координатами векторов. HTTP не выполняется внутри транзакции вызывающего кода.

Серверные исполнители запускаются через публичный механизм длительных операций БСП. Общая квота потоков БСП ограничивает фактическую одновременность всех операций базы. На проверенном стенде квота равна пяти: координатор и до четырёх исполнителей. Несколько координаторов разделяют эту квоту. Сам модуль не повышает её и не создаёт новые регламентные задания.

Результат содержит числа `Выбрано`, `Подтверждено`, `Ошибок`, `Пропущено`, `Пакетов`. Подтверждено означает завершение условной операции Qdrant и удаление именно этой версии задания. Это не число HTTP-запросов и не полная нагрузочная метрика.

## Порядок и защита от старых операций

Каждый фрагмент относится к одному из 16 постоянных разделов независимо от числа исполнителей. У раздела один владелец. Живое фоновое задание не вытесняется по одному лишь истечению срока; отсутствующее или завершённое задание допускает восстановление. Владение синхронного исполнителя ограничено сроком 600 секунд и продлевается перед порциями. Даже при потере владения версионное условие на стороне Qdrant сохраняет защиту от старой записи.

Постоянный счётчик для пары «фрагмент, модель» не удаляется после подтверждения. Новая версия больше предыдущей и не уменьшается при переводе часов назад. Повторная постановка заменяет прежнее задание и сбрасывает счётчик отказов. Подтверждение и запись ошибки сверяют текущую версию в базе: ответ старой отправки не удаляет новое задание и не меняет его попытки.

Для внешней записи используется `/points/batch?wait=true&ordering=strong` и условие по `_kii_revision`. Сервер Qdrant должен поддерживать условный `upsert` с `update_filter`; проверяется версия 1.16 или новее. Фактическая проверка выполнена на 1.18.2. Ответ считается подтверждением только при полном массиве завершённых результатов.

Удаление заменяет точку служебной заглушкой: без текста и вектора, с `_kii_revision` и `_kii_deleted`. Она не участвует в векторном поиске, но не позволяет запоздалому обновлению вернуть старый вектор. Новая версия после удаления может восстановить точку. Заглушки нельзя физически удалять, пока возможны старые отправки.

Защита предполагает, что все писатели используют этот протокол. Старые версии расширения и внешние безусловные записи обходят проверку версии. При переходе необходимо остановить прежние обработчики и завершить их запросы.

## Отказы и восстановление

После конфликта создания коллекции выполняется до пяти проверок её параметров. Временные HTTP 404, 408, 429 и 5xx из разрешённого набора допускают повтор; HTTP 401/403 и несовместимые параметры отклоняются сразу. В уже существующем фоновом задании БСП задержки перед повторами равны 0,25; 0,5; 1 и 2 секундам. В синхронном вызове выполняются ограниченные чтения без паузы пользовательского сеанса и без дополнительных фоновых заданий. Исчерпание проверок сохраняет задание для следующего прохода.

При ошибке HTTP пакет делится для изоляции плохого задания; число запросов деления ограничено деревом пакета. Уже принятые операции безопасно повторяются с той же версией. Недостаточный или повреждённый ответ HTTP 200 не подтверждает очередь. Задания с десятью отказами исключаются из обычного прохода; повторная постановка включает их снова.

Перед чтением векторов проверяются модель, удаление владельца и политика внешней отправки. Запрещённый вектор не распаковывается и не передаётся наружу; вместо него ставится новая версия удаления. Повреждённое хранилище вектора не блокирует подтверждение соседних исправных точек.

Старые строки очереди без версии обновляются ограниченными порциями, с сохранением порядкового номера, времени постановки, ошибки и числа попыток. Миграция не требует перезагрузки информационной базы из DT.

## Экземпляр базы, копии и обновление индекса

Имя коллекции зависит от штатного идентификатора экземпляра БСП, модели, размерности и версии схемы. Оно одинаково в COM и фоновых заданиях и не зависит от записи адреса сервера как `localhost` или `имя:порт`.

Каждое обращение к Qdrant проверяет публичную блокировку внешних ресурсов БСП. Для копии базы администратор должен выполнить штатное определение назначения базы. Подтверждение копии средствами БСП создаёт новый идентификатор экземпляра. Перемещение той же базы может сохранить идентификатор. Программа сама не снимает блокировку и не объявляет базу копией.

При первом переходе с прежней схемы имени коллекции снимаются отметки готовности индекса. Размерности сохраняются. Изменение отметок и кеша идентификатора выполняется одной короткой транзакцией с управляемыми блокировками. После этого нужна пересборка коллекций используемых моделей. До успешной пересборки старые отметки не дают новому частичному индексу считаться готовым.

Старая коллекция не удаляется автоматически. Её удаление — отдельная операция администратора после проверки новой коллекции и завершения старых писателей. Обратный переход на 1.6.3 без подготовки индексов и остановки новой очереди не является проверенным сценарием отката.

## Права и границы поставки

Добавлены регистры постоянных версий и владельцев разделов. В роли `КИИ_ПолныеПрава` им выданы чтение и изменение; остальные роли автоматически не расширяются. Новые модули не привилегированные. В изменённом RAG удалены собственные переключения привилегированного режима при записи идентификатора. Штатные публичные функции БСП сохраняют поведение базовой конфигурации.

Тесты выполняются с полными правами на отдельном стенде. Они не доказывают работу всех профилей конечных пользователей. Проверка 50–200 одновременных пользователей, производственные замеры скорости RAG и перенос в ИИ Экзаменатор выполняются отдельными этапами.

Общая декларация внешних ресурсов унаследованной ИИконы для профилей безопасности БСП требует отдельного аудита. Эта проверка очереди не подтверждает полную сертификацию продукта.

## Исправление политики знаний в 1.7.1

Отсутствующая или удалённая база знаний и неизвестная наследуемая политика запрещают внешнюю отправку. Явная политика базы имеет приоритет; пустая необязательная категория допустима. Параметры и протокол очереди не изменены. После 1.7.0 повторная пересборка индекса для этого исправления не нужна; при переходе с 1.6.3 сохраняется описанный выше порядок.
