# ИИкона 1.8.2: совместимость JSON и настройка подключений

Убрана зависимость прикладного кода ИИконы от функций БСП
`ОбщегоНазначения.ЗначениеВJSON` и `ОбщегоНазначения.JSONВЗначение`.
Если в старой конфигурации этих функций нет, обращение к HTTP-сервису
больше не должно обрываться на их вызове. Средства платформы используются
во всём связанном пути: HTTP-ответы и ошибки, аудит, подключения к другим базам,
запросы к модели, контекст диалога и настройки мониторинга.

Существующие публичные вызовы и форматы JSON сохранены. Прежний разбор аргументов
инструмента с допуском некорректного JSON остаётся отдельным механизмом.
Ошибочный JSON внешнего ответа не превращается в пустой успешный результат.

Руководство дополнено настройкой IIS для входа пользователем информационной базы:
разделены проверка Windows на веб-сервере, штатный вход в 1С и реквизиты прежнего API `/rpc`.
Добавлен корректный пример `ping` для `/connection`. Тело `{}` не является запросом MCP
и должно давать ошибку протокола; одного HTTP 200 недостаточно для подтверждения успеха.

В выпуск входят и возможности 1.8.1: получение больших списков метаданных частями,
пределы агентской петли в карточке модели и отдельная оценка расходов по тарифам.

Для обновления загрузите CFE в **существующее расширение** центральной и целевой баз.
Повторная загрузка данных не нужна. Структура прикладных данных и ролевые правила
не изменялись; модели, пользователи, настройки и сохранённые ключи сохраняются.

Устранение зависимости от двух JSON-функций не означает проверенную совместимость
со всеми старыми или доработанными конфигурациями. Безопасное хранилище и управление
доступом БСП продолжают использоваться. Точная версия БСП старой УТ из пользовательского
отчёта не установлена, эта база разработчику не предоставлялась.
Проверенный состав и фактические результаты приведены в `VERIFICATION.json`.
