# ИИкона 1.7.0

Пакетная очередь синхронизации Qdrant и несколько исполнителей. Выпуск от 11 октября 2026 года.

## Что изменилось

- По умолчанию отправляются пакеты до 32 операций; настраиваемый предел — 64. Один проход выбирает до 256 заданий.
- Серверная база использует до четырёх исполнителей через публичный механизм длительных операций БСП. Файловая база обрабатывает очередь синхронно. Фактическая одновременность учитывает общую квоту потоков БСП.
- Постоянная версия пары «фрагмент, модель» сохраняется после подтверждения. Повторная постановка увеличивает версию и сбрасывает число отказов. Старое подтверждение или ошибка не изменяют новое задание.
- Удаление оставляет в Qdrant служебную заглушку без текста и вектора. Запоздалое обновление не возвращает удалённый вектор; старое удаление не уничтожает новую версию точки.
- Пакет с отказом делится для изоляции плохой операции. Частично принятые операции безопасно повторяются. Неполный ответ HTTP 200 не подтверждает задания.
- Исполнители владеют постоянными разделами. Исчезнувшее фоновое задание допускает восстановление; живое не вытесняется по одному лишь истечению срока.
- Идентификатор коллекций одинаков в COM и фоновых заданиях: используется штатный идентификатор экземпляра БСП. Соблюдается блокировка внешних ресурсов для копии базы.
- Исправлена нормализация UUID с пробелами и верхним регистром. Временная недоступность параметров коллекции после конфликта её создания проверяется ограниченными повторами. Другая размерность, метрика или отказ доступа остаются ошибками.

Прежние вызовы постановки, обработки и пересборки сохранены. Собственные переключения привилегированного режима при записи идентификатора удалены. Новые модули не привилегированные.

## Требования

Для версии 1.7.0 требуется платформа 1С:Предприятие 8.3.27 или новее; проверена 8.3.27.1989 с БСП 3.1.11.392. Для нового условного протокола очередь проверяет Qdrant 1.16 или новее; фактические испытания выполнены на 1.18.2. Встроенный поиск RAG не требует Qdrant.

## Обновление с 1.6.3

1. Сделайте резервную копию. Остановите прежние обработчики очереди и дождитесь завершения их HTTP-запросов. Закройте сеансы и внешние соединения, использующие обновляемое расширение.
2. Установите CFE поверх существующего расширения штатным способом, обновите конфигурацию базы данных и перезапустите сеансы. Не перезагружайте базу из DT. Проверка обновления выполнена Конфигуратором при закрытых соединениях.
3. Проверьте штатное определение копии или перемещения базы в БСП. Программа не снимает блокировку внешних ресурсов за администратора.
4. Пересоберите коллекции используемых моделей Qdrant. Схема идентификатора контура изменилась; прежние отметки готовности снимаются, размерности сохраняются. До успешной пересборки новый частичный индекс не считается готовым. Векторы в 1С сохраняются, повторно получать их у платной модели для этой миграции не требуется.
5. Проверьте поиск и очередь. Старые коллекции удаляйте отдельно после приёмки нового индекса и завершения прежних писателей.

Старые строки очереди без версии обновляются ограниченными порциями при обработке; порядковый номер и накопленные ошибки сохраняются до отправки. На проверочной копии сохранены данные справочников, пользователи и доступность ранее записанных векторов.

Все писатели должны использовать новый условный протокол. Безусловная запись из старого расширения или сторонней программы обходит защиту версии. Заглушки удаления нельзя физически очищать, пока возможны старые отправки. Обратный переход на 1.6.3 с новыми индексами отдельно не проверялся.

## Проверки

- 693 серверных теста YAxUnit: 653 прежних и 40 новых. Падений, ошибок и пропусков нет; свежий JUnit проверен независимым разбором ожидаемого состава.
- SQL-стенд: фактическая одновременность одного, двух и четырёх исполнителей, два пересекающихся координатора без дублирования 64 заданий, повторная постановка удаления во время отправки.
- Настоящий Qdrant: четыре исполнителя используют одну коллекцию; удаление исключает вектор из поиска, позднее обновление блокируется; новая постановка восстанавливает точку, старое удаление блокируется.
- Установка CFE поверх отдельной копии 1.6.3: модели, эксперт, знания, векторы и пользователи сохранены; старые задания мигрируют и подтверждаются; готовность прежнего контура сбрасывается с сохранением размерности.
- SonarQube: Quality Gate OK, открытых замечаний в продукте и четырёх выбранных тестовых модулях нет. Новых исключений для очереди не добавлено; правила анализа не отключались.
- EDT: ошибок продукта нет; сохраняются 35 прежних предупреждений. Изменённые модули, регистры и тесты без ошибок и предупреждений.

Контрольный прогон 64 синтетических заданий с локальным имитатором HTTP дал 3,221 / 1,569 / 1,139 секунды для одного, двух и четырёх исполнителей. Это проверка параллельного механизма; производственная скорость NAS и нагрузка 50–200 пользователей требуют отдельных замеров. Платные запросы моделей в этой итерации не выполнялись.

Проверки с полными правами не подтверждают все пользовательские профили. Общая декларация внешних ресурсов унаследованной ИИконы для профилей безопасности БСП остаётся отдельной работой. Весь старый тестовый код не объявляется статически чистым; сертификация 1С:Совместимо не заявлена.
